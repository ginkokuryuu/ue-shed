# UE Shed 0.14.0

UE Shed 0.14.0 moves the published libraries to stable Effect 4.0.4 as a shared peer dependency,
bases Game Text's saved text coverage on each package's own gatherable text table, makes
localization quality checks run over the index at scale, moves Map History to `p4client-ts` 0.13.0,
and launches UE4 projects. All 20 public npm packages and eleven Unreal plugins advance to 0.14.0
together; packages without direct changes advance for suite alignment and exact dependencies.

## Effect 4.0.4 as a peer dependency

- Published libraries now require the application to provide `effect@^4.0.0` as a peer dependency,
  so UE Shed shares the application's Effect runtime. `@ue-shed/observability` also requires
  `@effect/opentelemetry@^4.0.0`.
- Renamed schema and configuration APIs, JSON Schema validation, synchronous cache queries,
  retained resource cleanup and Remote Control response handling are updated for Effect 4.0.4.
  Wire contracts and workflow behavior are unchanged.

## Game Text: saved text coverage from the gather table

- Saved text coverage follows the package's own gatherable text table, the list Unreal's asset
  gather reads. A package is partial only when a runtime entry from that table was not decoded.
  Undecodable properties that hold no gatherable text (native Niagara structs, for example) remain
  reported as coverage gaps without making the package partial.
- The table is used only where Unreal's gather would use it. Blueprints with bytecode, which are
  saved without one, keep the previous decoder-gap rule.
- Entries match on namespace, key and source text, so an unread source variant under a decoded key
  stays missing; authored bracketed namespaces are compared as Unreal saved them.
- uasset-io v1.10 adds `gatherCoverage` to package text records. Game Text adds
  `coverage.missingGatherableText` and `gatherable_text_not_decoded` diagnostics with the unread
  source text and Unreal site.
- User-defined enum display names are read as text. UE 5.8 user-defined enums, which save an extra
  underlying-type byte, now decode instead of failing.

## Game Text: localization quality at scale

- An opened index offers `localizationQuality(options, ruleDocument)`. It checks lines in bounded
  pages of 256 and keeps findings as columns; pages, focus and proposals re-check only the rows they
  show. `localizationQualityWorkspaceOf(source, quality)` builds the same workspace over either
  form, and `localizationQuality(report, join)` is the in-memory form for adapters without an index.
  `localizationQualityWorkspace(source, report, join)` is unchanged.
- `checkLocalizationLine` and the per-line policy and accepted-finding helpers expose the checks
  `checkLocalizationTarget` runs, one line at a time.
- Localization finding IDs are a fast hash of the finding's line, culture, rule and values. They stay
  stable across rescans of unchanged text; IDs from older versions do not resolve.
- `localizationLines` reads in bulk: rows hydrate in storage order in pages of adjacent rows, each
  evidence file's rows decode once per page, and shared strings decode in ID order. A 238k-line,
  10-culture target that previously ran out of memory after 40 minutes now completes.
- Evidence entries read from the index are no longer schema-decoded one by one; the importer
  validates Unreal's files when it writes the index, and checksums guard the index's bytes. On a
  generated 583,507-line, 10-culture target the quality scan fell from about 205 s to 115 s and its
  longest pause from 4–5 s to 0.5–0.7 s.

## Map History: p4client-ts 0.13.0

- `@ue-shed/map-history` requires `p4client-ts@0.13.0` (previously 0.12.1) and runs Perforce
  commands through its native Effect `P4` layer on the application's Effect runtime.
- `perforceHistorySourceLayer` accepts p4client-ts 0.13's `P4ClientOptions`, which move the
  top-level `port`, `user`, `client` and `charset` into `connection`, plus an optional layer factory
  for tests. Perforce configuration failures still map to `perforce_configuration`.

## Engine: UE4 projects

- The project launcher and supervised editor sessions use `UE4Editor` binaries and
  `UE4Editor.modules` manifests for 4.x engines, so 4.27 launches no longer fail with
  `editor_missing` or report the Remote Control check as unverifiable.
- `unrealEditorExecutable`, `validateUnrealProjectBuildId` and `validateUnrealRemoteControlBuild`
  take an optional `EngineVersion`; omitting it keeps UE5 naming.
- On macOS, `unrealEditorExecutable` returns the binary inside the editor's app bundle.

## Upgrade notes

Use matching 0.14.0 packages and plugin artifacts. Install Effect in the application alongside the
packages; Map History consumers also install the exact `p4client-ts@0.13.0`:

```powershell
npm install --save-exact @ue-shed/map-history @ue-shed/protocol @ue-shed/unreal-assets effect@4.0.4 p4client-ts@0.13.0
```

Map History callers that pass `port`, `user`, `client` or `charset` at the top level of
`perforceHistorySourceLayer` options move them into `connection`. Stored localization finding IDs
from earlier versions no longer resolve and should be re-accepted after a rescan.

Unreal plugins have no behavioral changes in this release; they advance for suite alignment.
Native plugin compatibility targets Unreal 5.7 and 5.8. Compiled variants require matching engine
version, BuildId, platform and architecture.

  the host discovered 13 fixture DataTables and opened a saved table.

  worktree of the release commit with no prior build output.

  gatherable text table and UE 5.8 user-defined enum decoding. The optional UE 4.27 legacy-fixture
  lane passed with matching evidence; the optional UE 5.3 lane was skipped because no installation

- Plugin compatibility (`pnpm test:unreal-plugins`): all eleven plugins built and 35 native tests
  passed on UE 5.7 and on UE 5.8.
- Trusted Unreal fixture gate (`pnpm check:unreal`) was not rerun. No Unreal plugin source changed
  since 0.13.0; plugin descriptors change only their version. Saved-asset parser and fixture changes
  are covered by the engine matrix on UE 5.7 and 5.8.
- All 20 packages were published from `7a95069d` with `pnpm release --checked`, which reused the
  portable gate above.
