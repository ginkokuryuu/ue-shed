# UE Shed 0.12.0

UE Shed 0.12.0 makes Game Text faster to open and rescan, keeps review work recoverable across
refreshes, and adds composable map source planning with native screenshot warmup. All 20 public npm
packages and eleven Unreal plugins advance to 0.12.0 together; packages without direct changes
advance for suite alignment and exact dependencies.

## Game Text performance

- Hosts compose project opening and refresh, localization import, target construction and query
  opening through `GameTextIndexSteps`. A project's source and localization target indexes share
  package extraction and strings, while each target keeps an independent joined view.
  `GameTextIndexRefresh` remains a compatibility wrapper.
- Workbench prepares one target-first model for source and localization browsing and validates its
  inputs before reusing it. Overlapping immutable readers share scoped query workers, and unchanged
  rescans keep healthy workers. An unchanged refresh replaces a worker that fails after readiness,
  and retiring the failed worker cannot evict its replacement.
- Validated target handles and their opened models expose an optional opaque query identity, so
  hosts can compare models without constructing or parsing storage identifiers.
- Cold preparation reserves memory by input size instead of probing the largest file first, sorts
  bounded string runs in workers, batches large package reads and converts larger staged layers in
  workers. Saved-text extraction uses bounded ordered native delivery and keeps package signature
  checks before and after reads.
- A bounded, optional source-query projection lets reopened readers reuse verified source bytes,
  ASCII flags and trigram membership. Query warming is limited to presentation pages.
- Saved package inventory, extraction, localization preparation, index construction and joined
  index opening report optional, operation-scoped progress.

On the same 583,507-line Workbench workload, before and after the shared-model and worker changes:

| Measurement                    |      Before |      After |
| ------------------------------ | ----------: | ---------: |
| Cold click to usable results   |   178.962 s |  126.842 s |
| Rescan after a cold scan       |    13.114 s |    2.563 s |
| Cached scan in a fresh process |     6.257 s |    4.809 s |
| Subsequent rescan              |    11.912 s |    2.463 s |
| Fresh settled derived cache    | 140.824 MiB | 81.776 MiB |

## Game Text review and recovery

- Typed translations, staged edits, open groups, loaded pages and scroll position survive rescans
  and writes. Drafts recover per project and target, including incomplete rule fields.
- Partial PO writes report what was written and retain unwritten or newer staged edits. Unstage and
  discard can be undone. Bulk review applies only to current translations, with confirmation and
  progress.
- Failed searches, groups and translation loads offer retries without rescanning. Source browsing
  remains available when localization fails, and recovery guidance from typed client errors reaches
  the user.
- Popovers, submenus, line navigation and view controls are keyboard accessible. Translation fields
  carry language and direction metadata. The workspace remains usable at 1024 px.
- Localization quality findings export with the selected target, culture and check filter, apply
  the target's review file and replay through the CLI from a preset.

## Map capture sources and screenshot warmup

- `planMapTileSources` lazily plans source footprints for a selected zoom, and `createMapTileSource`
  describes one rectangular block for capture or retry. Hosts choose individual tiles or larger
  blocks per zoom. Explicit dimension and decoded-memory limits include outer gutters.
- `cropMapTileImage` copies RGBA8 pixels exactly. `deriveMapTileParent` reduces four children in
  linear light with alpha weighting. Both are available from the root, map-tiles and browser entry
  points.
- The editor-viewport renderer accepts optional `renderer.screenshotWarmupFrames` (1–256), separate
  from viewport settling. The native override restores the engine's original value and priority
  after each frame and on interruption, and leaves external writes intact. Omitting the setting
  keeps existing engine and project behavior.
- Warmup support is discovered through the explicit `cameras.render-session.capabilities.v2`
  capability and `GetCameraRenderCapabilitiesV2`. The original capability getter keeps its exact v1
  response, so existing strict clients are unaffected.

## Upgrade notes

Use matching 0.12.0 packages and plugin artifacts. Screenshot warmup requires the 0.12.0 Cameras
and Core plugins; clients reject a warmup request before acquisition when the plugin does not
advertise the v2 capability.

`@ue-shed/game-text` now declares Node `^22.15.0 || >=23.8.0`, matching the built-in Zstd APIs its
Node entry point requires. Other packages still declare Node 22.14 as their minimum.

Localization quality presets and exports carrying `workspaceFilter` use schema version 2. Older
readers reject them instead of silently dropping the filter. Version-1 corpus and source quality
investigations remain readable and keep their format when replayed.

Encoded Game Text target storage keys are replaced by explicit project views. Hosts that used the
existing refresh service need no change; hosts composing their own pipeline should use
`GameTextIndexSteps`.

Native plugin compatibility targets Unreal 5.7 and 5.8. Compiled variants require matching engine
version, BuildId, platform and architecture.

## Validation

Release preparation on 2026-10-13 uses Node 26.11.1 and pnpm 11.17.0.

- Portable gate (`pnpm check`): passed with one Vitest worker. 2,522 tests passed and 51 explicitly
  gated tests skipped; all 20 packed packages passed clean offline consumer conformance.
- Data Authoring adoption conformance passed in a temporary workspace outside the source checkout:
  the copied host built, theme divergence changed production CSS, and the host discovered 13
  fixture DataTables and opened a saved table. The adoption manifest now copies the shared tool
  button, icon and focus modules.
- Plugin compatibility (`pnpm test:unreal-plugins`): all eleven plugins built and 35 native tests
  passed on UE 5.7 and on UE 5.8, including `ScreenshotWarmup` and `ScreenshotOwnership`. Two tests
  on 5.7 and one on 5.8 passed with expected log warnings: `TextIdentity` deliberately resolves a
  missing String Table entry, and on 5.7 `Niagara.IndependentCamera` reported the absent optional
  engine `M_Grid` material.
- Engine matrix (`pnpm test:uasset-engine-matrix`): passed on UE 5.7 and UE 5.8. The optional UE 4.27
  legacy-fixture lane passed with matching evidence; the optional UE 5.3 lane was skipped because
  no installation was configured.
- Trusted Unreal fixture gate (`pnpm check:unreal`) on UE 5.7: passed saved-asset conformance,
  13 native coverage tests, authoring mutation, Niagara rendering, 22 capture integration tests and
  all five Map Review end-to-end tests. Generated tracked fixture assets were restored after
  verification.
- The full trusted fixture gate uses the committed UE 5.7 contract and was not run on UE 5.8;
  UE 5.8 verification covered plugins and the engine matrix.
- Localization process conformance (`pnpm test:localization-processes`) was not rerun:
  `@ue-shed/localization` and the Unreal localization process orchestration have no changes since
  0.11.0 beyond suite version alignment.
