# UE Shed 0.11.0

UE Shed 0.11.0 improves localization review, keeps large Game Text projects responsive, and adds
saved map ownership and decode evidence. All 20 public npm packages and eleven Unreal plugins
advance to 0.11.0 together; packages without direct changes advance for suite alignment and exact
dependencies.

## Localization review and preparation

- Filter and group text by problem, translation state, culture, origin, folder, asset and namespace.
  Saved investigations retain localization targets, filter clauses and grouping; exports follow
  the same selection as the list. Export one CSV with native text and every selected language.
- Track localization key changes across saved assets and gathers, including baseline comparisons.
  Saved package namespaces now join the same namespace and key that Unreal gathers, while asset
  inspection retains the full saved namespace.
- `ue-shed loc gate` checks text touched by changed files before submission. Translation loss from
  key changes, conflicting sources and changed translated text fail by default; project policy can
  select which findings fail or warn.
- The new `prepare` operation runs gather and PO export in one Unreal GatherText process.
  Translation change sets treat absent and empty previous translations consistently, so a
  translation carried to a changed key remains current after gather.
- Larger evidence limits and streamed parsing support large targets with typed file and position
  errors. Manifest and archive loaders reject escaped unpaired UTF-16 surrogates like UE 5.7 and
  5.8; saved package strings retain their original code units.

## Game Text performance and recovery

- CLI and Workbench use a persistent column index with a shared string store, compressed,
  checksummed snapshots and atomic publication under one writer lease. Refreshes reuse unchanged
  packages and localization files, with committed Project Index signatures and Unreal's gather
  eligibility guiding saved-text extraction.
- Stream one compact text record per package, retaining complete coverage-gap counts and bounded
  samples. Reports bound diagnostic lists while preserving totals and omitted counts.
- Desktop and trusted Node hosts search through scoped workers. Replaced searches cancel, existing
  readers remain pinned through refresh, and superseded refreshes cannot publish over current data.
  Failed current localization inputs appear unavailable instead of reusing stale evidence.
- Shared strings preserve lone UTF-16 surrogates through canonical WTF-8. Disposable older index
  caches rebuild automatically. The previous large-heap setup requirement is removed.

## Saved map evidence

- Saved-world contract 2.1 adds actor decode status, saved parent-component references and `heldBy`
  ownership when a child-actor component names an actor owned by another saved actor.
- `packageErrors` records unreadable packages and exports, including whether an actor may have been
  lost. Undecoded property values produce bounded per-package summaries; use
  `uasset saved-world --skipped-properties export` for per-export details.
- Binary core structs inside containers decode without treating them as tagged property streams.
  Unknown container structs require tag evidence before tagged decoding; unsupported values are
  skipped with a reason. Landscape heightmap edge-fixup exports no longer produce false failures.

## Local editor responsiveness

On Windows, trusted local hosts can hold a scoped Core foreground-responsiveness lease to keep
Unreal responsive while the host is in front. The lease is restricted to loopback endpoints,
renews while held, recovers after editor restarts and releases when its scope closes.

The Data Authoring adoption manifest includes the new protocol module, so copied hosts continue
to build independently. The standalone consumer declares shared Node typings at its workspace
root, and adoption conformance runs outside the source checkout to verify dependency isolation.

## Upgrade notes

Use matching 0.11.0 packages and plugin artifacts. Saved-world 2.0 documents still decode; hosts
that pin the saved-world minor version to zero must accept minor version 1. New fields are optional.

Localization target PO evidence now exposes decoded entries in `value.entries`. Hosts constructing
evidence from a full parsed PO document should use `projectPOEvidence`; `parsePO` and `serializePO`
retain their existing types and byte-exact behavior.

Native plugin compatibility targets Unreal 5.7 and 5.8. Foreground responsiveness requires the
0.11.0 Core plugin. Compiled variants require matching engine version, BuildId, platform and
architecture.
