Add version 3 of the Game Text rule file. A v3 file sets each built-in check's policy under `checks`, keyed by check ID: `enabled`, `severity`, `scope` (roles, cultures, object path prefixes) and `params` (the catalogue's parameters, every field defaulted), over a `preset` of `default` or `none`. Version 3 rejects unknown keys, so a misspelt check or parameter is an `invalid_structure` error, and a v3 file may hold check settings alone. Checks now read their thresholds, word lists and severity from the resolved settings: `resolveLocalizationChecks(document)` returns them, and `migrateGameTextRuleDocument(document)` rewrites a v1 or v2 file as v3 with the same behaviour. The tag and argument lists become parameters of the checks that read them (`optionalTags` on `rich_text_tags` and `rich_text_tags_added`; `optionalArguments` on those two and on `format_arguments`, `format_argument_renamed` and `rich_text_tag_case`), and `segmentSeparator` becomes `segment_separator`'s `separator`. V1 and v2 files keep loading with the same findings. Reports' `ruleDocumentVersion` can now be 3. Scope is decoded and validated (unknown roles are `unknown_role_id`) but is not applied to findings yet: that comes with scoped checks.

**Breaking.** `quality-rules-v2.ts` is renamed `game-text-rules.ts`. Package-root imports are unchanged; deep imports must follow the rename. `GameTextRuleDocument` gains a third member, `TextQualityRuleDocumentV3`, and `LocalizationLineCheckContext` replaces `segmentSeparator`, `optionalTags` and `optionalArguments` with `checks` and `lists`. `localizationTranslationVariants` takes the `inconsistent_translation` parameters as an optional third argument. The rule-file error recovery text now names version 3.

Migration: code that switches on `document.schemaVersion === 2` to read `localizationRules` should test `schemaVersion !== 1`, because v3 has them too. Code that reads `segmentSeparator`, `optionalTags`, `optionalArguments` or `disabledLocalizationChecks` from a document should read `resolveLocalizationChecks(document)[id]` instead, which covers every version. To upgrade a stored v1 or v2 file, write `migrateGameTextRuleDocument(document)`.
